## 日常服务部署

复验发现日常端口 8787 的 Relay 与 Collector 仍由旧 `b1dc` 工作区运行，不能接收本轮新增的审批协议。核实旧父子进程身份后，经原 launcher 的 TERM 清理退出，再由当前 `aa09` 工作区的已构建 dist 启动两项服务。使用既有 Node.js 24.13.0 和保存的 Codex / Usage 开关，更新 monitor 自有 Claude Hooks 至当前 adapter；Claude 手机决定桥仍维持关闭。

迁移前在用户的私有 state/backups 目录完成 Relay / Usage 的 SQLite 在线备份，并保存监控配置、checkpoint、outbox、sequence 及 Claude settings。迁移后比较确认原有设备令牌记录、installation identity、Usage epoch 与开始时间、两项监控开关均保留。新 Relay 已创建 `relay_approvals` 表，Collector socket 权限为 0600。Launcher 刷新过期配对 QR，不撤销既有手机令牌。

已核对两个新服务的 cwd 和启动入口属于 `aa09`，Collector 的 Unix 连接实际连到现有 Codex Desktop IPC socket。当前会话的 checkpoint 为 active / sessionOpen / main，身份有效，位于三个有效 active 会话中的第二位，未超出 native observer 的 128 项上限；offset 已追至 EOF。手机当前页面显示 `RELAY CONNECTED`，并展示真实 Codex 工作状态；近期 AndroidRuntime 错误采样为空。此处不归档包含真实会话标题的手机截图。

## 原生审批验证边界

独立的原生 IPC 采样已取得当前桌面会话的完整快照与连续 revision 补丁，证明只读订阅机制有效；最新采样为 v11 / revision 160 / requests=0 / activeFlags=[]。独立采样不替代运行中 Collector 的逐会话订阅证据，当前 Collector 的全局 `codex_approval_status_unavailable` 诊断也无法区分是哪个旧 active 会话失去 owner。已有协议、Observer、Relay、Android 回归通过；Claude 的隔离真机审批和实际五分钟计时证据另见 [2026-10-07 报告](issue23-2026-10-07.md)。

最初会话使用 `auto_review`。低风险调试提权请求被自动放行，原生 requests 为空，未观测到 `waitingOnApproval`；这份早期连接证据不能当作正向审批测试。最初向用户询问了手动审批测试配置，但后续静态核对仅确认 Desktop 识别 `approvals_reviewer=user|auto_review`，未确认独立 UI 切换入口；已纠正为无需寻找或修改未确认的设置，代理未自动修改审批策略。

## 后续真实 Codex 审批正向证据

用户再次要求触发审批并继续核对后，2026-10-08 北京时间 01:24:03.559，日常后端首次记录本会话的真实 Codex `approval_requested`：sequence 9810，request ID `902d8a69-121b-5e50-9eb2-eb5d1eba0855`，source=codex，status=pending，tool=Bash，can_respond=false。Relay 于 01:24:03.636 收到，延迟 77 毫秒。01:24:09.976 记录同一身份的 `approval_resolved`（sequence 9811），Relay 于 01:24:09.979 收到；原生 pending 持续约 6.417 秒，最终持久行是 resolved。

该记录来自运行中的日常 Collector 与 Relay，属于当前 root 的脱敏 session identity；数据库此前没有其他审批记录。本轮未运行隔离 fixture、未注入 Hook 或合成审批。本轮截图读取命令的提权审批期间出现这对原生事件，不能将其归因于前一条读取设备型号的请求。

实机截图直接显示 `RELAY CONNECTED`、`Handled on computer`、Bash、相同请求 UUID 和提醒剩余 `04:54`，并显示“待办已解除，执行结果请在电脑核对”。这证明真实 native pending 经生产链路到达手机后进入独立提醒页，解除后保持在原页；Codex 来源未出现手机 Allow / Deny 控件。截图取得时原生待办已经解除，因此直接截图证据是结果页，没有保存 `Awaiting approval` 页面，也不据此声称已验证本次五分钟完整等待。实际五分钟期限的既有独立真机验证仍以 2026-10-07 报告为准。

现场截图保存在本机临时调试目录，不将真实会话页面归档进仓库。此次正向证据补齐了真实 Codex 原生来源到手机结果提醒的链路；尚未增加原生问答支持或验证 App 进程死亡后的倒计时恢复。

## 按用户修正后的 15 秒结果页复验

首次原生截图中的 `04:54` 表明旧版在处理结果到达后仍按五分钟倒计时。修正版将规则改为：请求待处理时最多保留五分钟；首次收到已处理结果后，结果页从该时刻停留 15 秒再返回正常监控页。重复结果、刷新和普通进度不会重置这 15 秒，未知结果仍保留待处理提醒。

修正版在华为 DBR-W00 上通过五项 instrumentation/device 测试，包含 `handledResultWindow`：使用真实设备时钟、生产 Android UI、配对 WebSocket 与本地隔离 Relay/CLI fixture，处理 Allow 后先看到 `00:15` 结果页，再覆盖重复结果、刷新和无关进度，期限到达后回到最新 Usage 页面。Fixture 是合成测试数据，不执行用户的 Claude 请求。结果页计时使用生产 reducer；Codex resolved 状态由协议测试覆盖并共用这一 reducer。截图：[15 秒结果页](screenshots/issue23-2026-10-08/fifteen-second-result.png)、[期限结束后恢复 Usage](screenshots/issue23-2026-10-08/fifteen-second-latest-usage.png)。

Android 离线验证通过：172 项单元测试零失败、零错误（1 项既有 skip），`lintDebug`、Debug APK 与 instrumentation APK 构建均通过。真机五项测试全部通过，用时 22.123 秒。新版已安装并核对上述 APK SHA-256；测试后已移除 ADB reverse 和临时 fixture，重新打开普通监控页，既有应用数据与配对保留。
