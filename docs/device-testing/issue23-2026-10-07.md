## 已验证结果

`ApprovalReminderDeviceTest` 四项真机通过，耗时 4.959 秒。前两项使用注入的时钟和测试客户端，验证精确五分钟边界以及结果在原页更新、操作按钮消失；后两项使用界面状态 fixture，覆盖短横屏、大字号、并行歧义和提问/输入图标在 Status 与 Usage 页持续可见。这组测试证明真实设备上的界面和状态处理，不等于实等五分钟或真实网络链路。

`ApprovalRelayDeviceTest#questionLifecycle` 与 `#bridgeDecisions` 第一轮两项通过，耗时 8.728 秒。生产 `WebSocketMonitorClient`、`MonitorViewModel` 和 Compose 页面连接隔离的生产 Collector / Unix socket / SQLite Relay；提问提示跨 Status 和 Usage 保留，同会话无关 Bash 进度不清除，实际 WebSocket 重连及新 ViewModel 的快照恢复有效，匹配回答后图标消失。真实按钮分别交付 allow、deny、computer，结果仍显示在原审批页并关闭操作按钮。

最终严格 `#bridgeDecisions` 与 `#fiveMinutePin` 两项全部通过，整轮耗时 306.661 秒。真实 Node CLI 子进程必须退出 0；allow / deny 的实际 stdout 必须为 `PermissionRequest` 的官方决定 JSON，且 behavior 匹配；computer 的 stdout 必须精确为空、没有决定 JSON。以上断言均由设备测试实际验证，不只根据 Relay 收到决定判定成功。

五分钟方法使用生产 ViewModel 的默认单调时钟和 `SystemClock`，不注入时间，首个观测剩余时间为 299,958 毫秒。真实等待期间，重复请求/快照和无关进度未抢占页面或改变首次截止；选择“在电脑处理”后，结果原位更新且截止不变。到 elapsed 294,997 毫秒时仍剩 4,961 毫秒；随后按原截止退出，恢复最新 WORKING 对应的 Usage 页。最后截图后的观察为 elapsed 300,603 毫秒、剩余 0；这个数包含截图等收尾开销，不当作精确到期时刻。合计覆盖七个不同的真机用例，严格桥决定是同一用例的追加复验。

## 验证范围

隔离宿主 `tests/device-approval-relay.mjs` 使用临时目录和独立配对令牌，仅提供安全的合成 Claude Hook 元数据。审批通过真实 Node CLI 子进程、Unix socket、配对 WebSocket 和 SQLite Relay 返回官方 Hook 决定；没有启动 Claude 模型会话、执行任何 Claude 工具操作，或确认真实用户的审批。手机测试直接取得临时 fixture 配置，不读取或写入日常 `PairingStore`，也没有安装、更改或启用真实用户 Hooks。

设备截图保存至 app 的 `externalFilesDir/issue23-screenshots`，拉取后归档到本报告的截图目录；不归档真实会话屏幕或临时令牌。此轮没有验证 Codex 审批/问答、App 进程死亡后的期限恢复或所有 Claude sandbox network 权限来源。

## 最小复现与清理

仓库根目录使用 Node.js 24.13.0 构建后启动隔离服务，保持该终端运行：

```bash
PATH=/private/tmp/node-v24.13.0-darwin-arm64/bin:$PATH npm run build
DEVICE_TEST_PORT=18883 /private/tmp/node-v24.13.0-darwin-arm64/bin/node tests/device-approval-relay.mjs
```

另一终端构建、覆盖安装测试所用 APK，并建立本轮专用端口映射：

```bash
gradle :apps:android:assembleDebug :apps:android:assembleDebugAndroidTest
adb -P 5037 install -r apps/android/build/outputs/apk/debug/android-debug.apk
adb -P 5037 install -r apps/android/build/outputs/apk/androidTest/debug/android-debug-androidTest.apk
adb -P 5037 reverse tcp:18883 tcp:18883
adb -P 5037 shell am instrument -w -r \
  -e class com.example.claudephonemonitor.ui.ApprovalReminderDeviceTest \
  com.example.claudephonemonitor.test/androidx.test.runner.AndroidJUnitRunner
adb -P 5037 shell am instrument -w -r \
  -e class com.example.claudephonemonitor.ui.ApprovalRelayDeviceTest#questionLifecycle \
  -e deviceRelayUrl http://127.0.0.1:18883 \
  com.example.claudephonemonitor.test/androidx.test.runner.AndroidJUnitRunner
adb -P 5037 shell am instrument -w -r \
  -e class com.example.claudephonemonitor.ui.ApprovalRelayDeviceTest#bridgeDecisions,com.example.claudephonemonitor.ui.ApprovalRelayDeviceTest#fiveMinutePin \
  -e deviceRelayUrl http://127.0.0.1:18883 \
  -e timeout_msec 420000 \
  com.example.claudephonemonitor.test/androidx.test.runner.AndroidJUnitRunner
```

五分钟方法自身也设置 420,000 毫秒测试超时，每约三十秒输出 elapsed/time-left 元数据。测试前需解锁屏幕，窗口设置 `FLAG_KEEP_SCREEN_ON` 并在结束后恢复；本轮主代理另外临时设置设备充电时常亮为 7，原值为 0。

本轮清理已完成：隔离 fixture 经 Ctrl-C 正常退出 0，端口 18883 无监听；`adb reverse --list` 为空，专用端口映射已删除；设备充电时常亮恢复原值 0，日常 `MainActivity` 已重新打开并确认在前台。原配对和用户 Hooks 未改动，此次实机调试未修改生产代码。
