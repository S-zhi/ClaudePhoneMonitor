## 真实元数据计数修复

真实来源还使用 `source.subagent = { other: String }` 形式表示后台审核线程。原解析器只支持 `thread_spawn` 对象及部分字符串枚举，会误把这类线程算作主会话。本机一次只读采样中，九个已上报线程有三个主会话、六个子线程；旧解析器会错误识别为六个主会话。修复支持已核实的 `other` 字符串对象形式，仍拒绝缺失、空值、错误类型及未知对象格式，不按标题或父线程猜测。

Collector 81 项测试、memory/SQLite 四项链路测试、类型检查及 Collector 构建通过；回归覆盖已有 `main` checkpoint 分类纠正且不重放历史完成。真机链路 fixture 的一个子代理改用 `{ other: "guardian_review" }`，复验通过，耗时 22.434 秒，确认 `2 / 5 → 2 / 4`、完成名称与截止时间保留及仅子代理运行时 `0 / 8`。

常驻 Relay/Collector 已通过项目启动脚本切换为当前实现，原配对、安装身份、SQLite、Usage 统计和已开启的 Codex/Usage 监听保留。只读核查 Relay 存储中对应 Codex `guardian_review` 来源的 228 个历史线程，全部为 `subagent`；历史分类本身不构成 running。手机重新连接后已经显示明确统计而非 `—`；一次页面采样的主会话、主运行和总运行均为 `02`，会随着真实线程生命周期变化。复验临时服务与 USB 端口已清理，日常新版监控继续运行。
