# Issue 26 Android sound reminder verification (2026-10-08)

The formal `SoundReminderDeviceTest` ran on Huawei DBR-W00 (Android 12 / API 31) against main APK SHA-256 `b197ab695541dc5e885f86cbd973b9a3cff8c0aa969d5d0fc83b7e96960c5901`. App data and pairing were preserved. The final six-case run took 51.414 seconds: four passed, two were skipped, and none failed. The follow-up ran the two cases again in 12.357 seconds: notification-volume-zero passed, while vibrate was skipped because `Vibrator.hasVibrator()` returned false. Across the six distinct cases, the result is **five passed, one hardware skip, zero failures**; the runner's `OK (6 tests)` includes skipped tests and does not mean all six passed.

| Run | Scenario results |
| --- | --- |
| Formal suite (6 cases) | Pass: threshold/dedupe/queue/recreation, unseen initial-snapshot approval, silent ringer, DND. Skip: vibrate setter, notification-volume-zero setter. No failures. |
| Follow-up (2 cases) | Pass: notification-volume-zero with `ADJUST_MUTE` fallback. Skip: vibrate; device reports no vibrator hardware. No failures. |

The five passed cases produced 11 successful native `SoundPool.play()` stream IDs: six in the threshold/deduplication/queue/recreation case plus one new identity after ViewModel recreation, one unseen initial-snapshot approval, one fresh cue after silent-mode replay, one after DND replay, and one after zero-volume replay. Every counted stream ID was nonzero. The queued sounds were spaced by at least 557 ms, exceeding the 440 ms WAV duration. `AudioPlaybackCallback` reported zero callbacks on this OEM and was not used as playback evidence. The test uses the production Android player, ledger, ViewModel, and Compose screen with anonymous local JSON fixtures; it does not verify a live Claude/Codex upstream or LAN connection. Native stream requests were confirmed, but there was no recording or subjective listening check.

The vibrate case was skipped because this device has no vibrator hardware. The zero-notification-volume case read back volume 0 and `isStreamMute=true` while ringer mode remained NORMAL and DND remained off; replaying the consumed identity stayed silent, and a fresh identity produced one nonzero stream.

Final handset readback was notification volume 7/15, notification mute false, AudioService internal ringer NORMAL (2), external ringer SILENT (0), zen mode 1 / interruption filter PRIORITY (2), and notification-policy access revoked. Android Settings showed the sound/ring option selected. The external SILENT value is Huawei's priority-DND proxy; this check confirms the user-visible sound preference, internal NORMAL mode, volume, and DND profile, and does not claim that the external ringer API returned its earlier value 2. `stay_on_while_plugged_in=0` and `screen_off_timeout=300000` were unchanged. No app data or pairing state was cleared. After verification, the temporary instrumentation test package was uninstalled, and the regular app was opened with its pairing/data intact. The exact readbacks are recorded in [device-state-final.txt](issue26-2026-10-08/device-state-final.txt).

Before device verification, two preliminary runs exposed test-controller, Compose, and audio-readback issues; those runs are not acceptance results. The final instrumentation APK built successfully after the fixes. The Android JVM suite had 190 passes and one expected skip for the missing `CODEX_LIVE_WIRE_PATH`; lint had 0 errors and 20 baseline warnings. The generated reminder WAV is 440 ms, mono PCM16 at 22,050 Hz, without clipping.
