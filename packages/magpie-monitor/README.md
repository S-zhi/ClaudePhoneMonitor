# Magpie session monitor

This local OpenCode-shaped plugin observes Magpie session snapshots and safe native metadata. It does not register tools, providers, auth, or models. Relay forwarding is disabled unless explicitly enabled with a private config file. It launches only the short `magpie sessions --json --limit N` CLI command, with bounded time/output and a recursion guard.

The plugin writes sanitized snapshots and a bounded event journal under the host-provided `directory/monitor-sessions`. A SQLite `BEGIN IMMEDIATE` reservation gives one process write ownership; other hosts retry as standbys. Session IDs are hashed. Raw IDs, paths, prompts, cwd, resume commands, and cache text are never checkpointed.

Recent activity comes from Magpie snapshot timestamps and is recomputed on each poll. Execution status is separate and uses only a verified Codex rollout `session_meta` plus ordered turn events; fresh native activity can refresh an open turn, while old completed turns remain `idle` as the latest recorded outcome (not a claim about a live process or focus). Other agents remain `unknown` until an explicit native lifecycle source is supported. Rollout reads are bounded to an 8 MiB tail (64 KiB identity head), 1 MiB per line, and 64 MiB total per poll; incomplete or oversized evidence fails closed as `unknown`. Historical active time, when present in Magpie cache v19, is an estimate based on line gaps under five minutes.

Relay forwarding is opt-in: place a private `0600` `monitor-sessions/relay.json` in the host config directory with `relay_url`, `installation_id`, `collector_token`, and optional `sequence_floor`. The bridge tolerates the relay's initial unauthenticated negative hello acknowledgement, sends nothing until a later accepted acknowledgement, and waits up to five seconds for authentication. Explicit `unauthorized` blocks automatic retries while local monitoring and durable queuing continue; restart the host after correcting credentials. Events use an installation-scoped durable outbox and are removed only after accepted/duplicate ACKs. At most 100 session candidates are selected per poll, with additional revocations for previously published tasks; local plugin history is capped at 5,000 sessions, while Relay history snapshots are capped at 50. It sends metadata and verified Codex transitions with confirmed main/subagent classification; unsupported agents/kinds remain unknown, and the optional `source_execution_status: "unknown"` revocation requires a Relay version that supports this metadata extension. Unknown revokes a working claim without inventing a completion. Credentials, native IDs, paths, and prompts are not persisted in the outbox.

Run the isolated tests with `node --test packages/magpie-monitor/test/*.test.mjs`.
